How it works

From a sentence to an artifact you can check

The mission engine is deterministic and local: every stage below is implemented and covered by automated tests. No step is skipped, and nothing is reported as done unless the result on disk supports it.

  1. Goal

    You state the goal and pick the source file. The goal is the only input — there is no hidden prompt, and the mission starts as a draft.

  2. Mission planning

    The planner builds a step list and fixes the acceptance criteria before anything runs. Planning is rule-based, so a plan is reproducible rather than improvised.

  3. Permission & approval

    Nothing executes until you approve. Approvals are bound to a scope: the tool, the operation, the target and a digest of the parameters, with an expiry and single use.

  4. Execution

    Local tools run step by step — validate, load, profile, write, verify. Every attempt gets its own execution ID and is written to the audit trail as it happens.

  5. Verification

    The artifacts are read back from disk and re-checked with an independent implementation. A mismatch becomes “needs attention”, never a silent pass.

  6. Artifact delivery

    You get the report and the machine-readable profile with size and SHA-256, downloadable from the mission and listed with its evidence in the audit trail.

Trust & security

Built to show its work, not to promise magic

These are the mechanisms that exist in the shipped build. Where a limit exists, it is stated here rather than left for you to discover.

Permissions are enforced at the execution boundary

Eight operation-level permissions (file:read, file:write, network:out, credential:use, side-effect:external, plugin:exec, mcp:exec, process:exec) are checked in the server before an action runs — not only in the UI. Network, side-effect and credential permissions require real configuration plus an explicit confirmation.

Approvals are bound to one action

An approval covers a specific capability, operation, target and parameter digest, with an expiry, and is consumed after use. Changing the parameters invalidates it. Approving a mission is not a blank cheque for everything that runs inside it.

Append-only audit trail, with secrets redacted

Every mission and tool event is appended to a local JSONL log with an ID, timestamp, type, outcome and correlation ID. API keys, tokens and bearer credentials are redacted before writing, and user file contents are summarised (name, size, SHA-256) instead of copied.

Change detection on the trail

Events are hash-chained, so an edit to an already-written event is detected by the integrity check and reported with the line number. The log is rotated by size with a fixed number of retained generations.

What this build does not claim

  • The audit trail is not tamper-proof. Hash chaining detects changes to events already written; it does not stop someone who can rewrite the whole file. There is no cryptographic signature and no key management.
  • No security certification. Nothing here has been audited or certified by a third party. The controls above are implemented and covered by our own regression tests — that is the extent of the evidence.
  • Plugins run in-process and are not sandboxed; the plugin permission marks that action, it does not contain it.
  • Live provider calls are unverified here. Chat, vision and speech paths are exercised against a local mock; real model calls need your own provider key and have not been validated in this build.
  • Linux and macOS runtimes are unverified. The Windows build is tested end-to-end; the Linux and macOS artefacts exist but have not been executed on those operating systems.

FAQ

Straight answers

What does Dudu actually do today?

It turns a goal plus a data file into a mission with fixed acceptance criteria, asks for your approval, runs local tools, re-verifies the produced artifacts from disk, and gives you the report together with a complete audit trail. One mission template exists today: tabular data analysis (CSV, TSV, JSON, JSONL, XLSX). The planner is rule-based, not a model.

Which platforms can I use right now?

Windows 10/11 x64 is the verified one, as an installer or a portable binary. The web app runs on any machine you can run Node on, but it serves over HTTP from your own host. The Linux tarball is built but has not been executed on Linux yet, and macOS and mobile are not released.

Where does my data go?

Into your own operating system data folder: files, missions, artifacts and the audit trail live there. Nothing is uploaded to us, because there is no server to upload to. When you configure a model provider yourself, the prompts you send go to that provider — that request is made by your own key, on your own machine.

Do I need an API key?

For chat, vision and speech, yes: you add your own provider key, and it is stored server-side in your data folder, never in the front-end bundle. Without a key, the application still runs — it simply tells you honestly that the model features are not configured.

Can someone tamper with the audit log?

No, and we do not claim it is. Events are hash-chained, so altering an already-written event is detectable, and the integrity check tells you where the chain broke. But anyone who can rewrite the whole file can rebuild a valid chain, and there is no signature. Treat the trail as a strong local record, not as evidence for an adversary.

Can the agent act on its own?

No. A mission runs only after you approve it, and an approval covers one action, one set of parameters and a limited time. Effects outside the machine — for example calling a webhook — additionally require explicit confirmation, and the permission model refuses them otherwise.

Is there a paid plan?

No pricing has been published for Dudu. The current release runs locally with your own provider key and your own machine; there is no hosted subscription to buy yet. When commercial terms exist, they will be published before anything is charged.

How do I get the mobile app?

You cannot yet — no Android or iOS build exists. Join the waiting list and you will be told first when a beta is cut. Nothing on this page pretends otherwise.
